# Alle Versionen sind festgenagelt ("==" statt ">=").
#
# Warum: Mit ">=" hat jeder CI-Lauf stillschweigend die jeweils neuesten
# Bibliotheken eingesammelt. Der ausgelieferte Installer enthielt damit andere
# Versionen als der lokal geprüfte Build, und ein Fehler konnte allein dadurch
# entstehen, dass zwischen zwei Releases irgendwo eine neue Version erschien.
#
# Beim Anheben einer Zeile: App bauen, ein arabisches Buch mit bekannten
# Seitenzahlen einlesen, Seitenzahlen und semantische Suche gegenprüfen.
#
# Python 3.12 oder neuer wird vorausgesetzt (numpy 2.5 verlangt das); die CI
# und die Build-Skripte benutzen 3.12.

# ACHTUNG: fastembed NICHT ohne Not anheben.
# Ab Version 0.6.0 berechnet fastembed das Modell
# paraphrase-multilingual-MiniLM-L12-v2 mit Mean-Pooling statt wie vorher mit
# CLS-Pooling (fastembed warnt beim Laden ausdrücklich davor). Dieselbe
# Passage ergibt seitdem einen anderen Vektor.
# Die in den Nutzer-Datenbanken gespeicherten Vektoren (Tabelle
# passage_vectors) stammen von genau dieser Version. Wechselt man auf eine
# Version mit anderem Pooling, werden Suchanfrage und gespeicherte Vektoren
# gegeneinander gerechnet: die semantische Suche liefert dann Unsinn, ohne
# dass irgendwo ein Fehler erscheint - der schlimmste Fall, weil er unsichtbar
# ist. Ein Wechsel ist nur zusammen mit einem vollständigen Neu-Vektorisieren
# der ganzen Bibliothek möglich.
